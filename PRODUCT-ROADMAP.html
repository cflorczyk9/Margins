Margins
Product roadmap · updated 2026-05-10

Local files first. Claude and ChatGPT as the final surface.

Margins should become the setup and vault layer that turns a user's local files into a Claude/ChatGPT-operable Markdown wiki. The fastest beta uses BYO API keys. The end state uses Claude/ChatGPT connectors so normal foreground work rides on the user's existing subscription.

Core Promise

Pick a folder.
Margins creates a local vault.
Drop files into it.
Claude or ChatGPT can read, organize, and update the vault with citations.

Important Platform Reality

The standalone web app and the final connector product are related, but they do not use model compute the same way.

Do not build "log in with Claude/ChatGPT" as a hidden API substitute. Claude/ChatGPT subscriptions and developer APIs are separate products. Automating a consumer chat login from the Margins web app would be fragile, suspicious, and the wrong platform posture.

Standalone Margins

Runs in the browser or local helper. Direct model calls need BYO API key, local model, or Margins-managed compute.

Claude/ChatGPT Connector

User operates Margins inside Claude or ChatGPT. The host product supplies foreground reasoning through the user's subscription.

Margins' Role

Margins provides the vault, local file access, tools, operating rules, provenance, and write-back discipline.

End-State User Experience

The setup flow creates the local structure first. Uploads and connectors add to the same vault later.

Flow

  • User visits Margins and clicks Start locally.
  • User chooses a template: general, student, practitioner, investor, or custom.
  • Margins creates the folder structure.
  • User drops files into Margins.
  • Early mode processes files with a user-provided API key.
  • Final mode connects the vault to Claude/ChatGPT.
  • Claude/ChatGPT proposes changes and writes only after approval.

Architecture

Build the web app as the onboarding surface, then add the local helper and connector layer without changing the vault contract.

1. Web App

The onboarding and vault-management surface.

  • Landing/setup/app flow
  • Template and folder selection
  • Browser folder picker
  • API key setup for early direct processing
  • Inbox, retry, delete, approve
  • Wiki browser and vault health views

2. Local Helper

The bridge from browser prototype to trusted connector product.

  • Read/write selected vault folder
  • Store keys in .env or OS keychain
  • Expose local HTTP endpoints
  • Run long jobs outside the browser
  • Expose MCP tools

3. Connector Layer

The MCP/app layer that lets Claude and ChatGPT operate the vault.

  • Read tools for search and retrieval
  • Proposal tools for ingest and cleanup
  • Write tools only after approval
  • Clear provenance and operation logs

Roadmap Phases

Ship a credible local web beta first, then use the same vault as the foundation for Claude and ChatGPT.

0

Current Local Prototype

Mostly built. Browser app creates/opens local vaults, preserves raw files, and requires model review for source pages.

  • Setup wizard is not wired into real scaffolding yet.
  • API controls are still developer-style advanced settings.
  • No local helper or Claude/ChatGPT connector yet.
1

Public Web Beta

Get Margins into technical and semi-technical users' hands quickly.

  • Real landing/setup/app route flow.
  • Template picker from the original prototype.
  • Provider, model, API key, and spend guard setup.
  • Real template folder scaffolding.
  • Clean processing and error states.
Positioning: Margins organizes your files into a local Markdown wiki using your own model key.
2

Trust And Distribution Polish

Make API-key mode feel inspectable instead of sketchy.

  • Open-source repo linked from setup.
  • Use once, Clear key, and Clear local data.
  • No analytics or session replay on key setup.
  • Key never appears in logs, Markdown, URLs, or exports.
  • Visible "what leaves your computer" copy.
3

Local Helper

Reduce browser limitations and prepare for MCP.

  • margins-local install/run flow.
  • Localhost API for vault read/write.
  • Background jobs for books and long transcripts.
  • Local key storage outside the hosted page.
  • Folder watch mode for raw/.
Hosted web page = UI. Local helper = file access, secrets, and MCP server.
4

Claude Connector

Let users operate Margins from Claude using their existing Claude subscription for foreground work.

  • User runs margins-local.
  • User adds Margins as an MCP server in Claude.
  • Claude searches and reads the local vault.
  • Claude proposes ingest updates.
  • Margins writes approved Markdown back to disk.
First honest no-API-key story: use your Claude subscription to operate your Margins vault.
5

ChatGPT App / Connector

Provide the same existing-subscription path for ChatGPT users.

  • ChatGPT app/connector surface.
  • Tool descriptions tuned for ChatGPT tool selection.
  • Read-only tools first.
  • Proposal-write tools second.
  • Interactive setup/status component if useful.
6

Managed Convenience Layer

Make the product easier for non-technical users after the connector path is validated.

  • Account for preferences only.
  • Optional encrypted key vault.
  • Optional cloud job runner.
  • Optional setup-template sync, not document sync.
  • Paid managed inference for users who do not want API keys.

Product Modes

The same vault supports both direct use and connector use.

Direct Mode

User runs Margins directly.

  • BYO API key.
  • Local helper API key.
  • Local model.
  • Optional Margins-managed compute later.

Best for early beta, power users, and people who want a dedicated ingest app.

Connector Mode

User runs Margins through Claude or ChatGPT.

  • Claude/ChatGPT subscription supplies foreground model reasoning.
  • Margins provides vault tools and file writes.
  • Best for the final mainstream story.

Constraint: Margins is the tool layer, not the model.

Near-Term Implementation Checklist

The concrete bridge from current prototype to shippable product.

  1. Move the prototype setup wizard into the real app shell.
  2. Convert setup choices into a VaultSetupPlan.
  3. Update scaffoldVault() to accept the setup plan and create template folders.
  4. Move provider/model/API-key controls out of Advanced and into setup.
  5. Keep Advanced only for developer/debug controls.
  6. Add local-only key storage choices: Use once, Remember on this device.
  7. Add a trust panel explaining exactly what leaves the device.
  8. Add a demo mode that needs no key and writes no files.
  9. Build margins-local as the future MCP helper.
  10. Expose read-only MCP tools first, then proposal-write tools.

Success Criteria

What has to be true for Margins to feel real.

Fast Setup

A new user can create a local vault in under ten minutes.

Real Ingest

A user can drop a PDF, transcript, or book and get a cited source page without heuristic filler.

Portable Vault

The generated vault is readable in Obsidian, Finder, VS Code, Claude, and ChatGPT.

Trust

Users understand where their files and keys are stored.

No Extra API Fee

Claude can operate the same vault through MCP without a separate Margins API key for foreground work.

Strategic Bet

The durable product is the vault and operating layer. The model surface can change.
